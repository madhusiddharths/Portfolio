Overview

Upload a photo and get back the most visually similar images from Caltech-101, ranked in milliseconds. A fine-tuned ResNet-50 turns every image into a 128-dimensional embedding, FAISS searches those embeddings by cosine similarity, and a Streamlit app serves the whole thing as a live tool.

It was built over eight weeks in a Build Fellowship, one stage per week: environment, pretrained features, data-quality checks, a from-scratch baseline, transfer learning, evaluation, the deployed app and a final presentation. Each stage had to beat or justify the one before it.

Dataset

Caltech-101: 8,677 images across 101 object categories (animals, vehicles, instruments, household objects), with 40 to 800 images per class and a held-out validation split of 1,736 images. The uneven class sizes matter: a model can look accurate overall while failing the small classes, so evaluation reports per-class precision and recall, not just accuracy.

Before training, a data-quality pass flagged images that would poison the embeddings: blurred, too dark, overexposed, heavily compressed, or with dead pixels.

Data Preprocessing

Every image is converted to RGB, resized to 224×224 and normalised with ImageNet statistics, matching what ResNet-50 was pretrained on. Training images are augmented with random crops, flips, rotation, colour jitter, affine transforms and random erasing; validation images are only resized and normalised, so the validation score measures the model, not the augmentation.

Performance

A small CNN trained from scratch set the baseline at 73.68% validation accuracy. Swapping in ResNet-50 with ImageNet weights, a new embedding head (2048 → 512 → 128 with batch-norm, ReLU and 0.5 dropout) and a 101-class classifier on top, then fine-tuning the last residual block, reached 96.95% validation accuracy after 30 epochs with AdamW, cosine learning-rate annealing and label smoothing.

The classifier is there to shape the embedding space: training it to separate 101 classes pushes images of the same object close together, which is exactly what retrieval needs. Retrieval quality was then measured directly with top-K precision and mean reciprocal rank.

FAISS Vector Indexing

Embeddings are L2-normalised and stored in a FAISS IndexFlatIP. On unit vectors an inner product is cosine similarity, so an exact search returns the true nearest neighbours with no approximation error. At this scale (thousands of vectors) exact search answers in milliseconds, so an approximate index would add complexity without a speed benefit.

The index and image metadata are precomputed by a command-line script, and the app loads the model once (cached) and lets the user pick how many matches to return, from 1 to 10.

Deployment

The app runs on Streamlit Cloud. The trained weights (about 94 MB) live in Git LFS, which free hosts do not always fetch, so the app checks at startup whether the weights file is real or just an LFS pointer and pulls it if needed. That one check is the difference between a demo that works on a laptop and one that works for a visitor.

Conclusion

A from-scratch CNN reached 73.68%; transfer learning with a purpose-built embedding head reached 96.95%, and the same embeddings power exact cosine search in FAISS behind a deployed app. The useful lesson was to train for the embedding space retrieval needs, then measure retrieval itself rather than trusting classification accuracy as a stand-in.
