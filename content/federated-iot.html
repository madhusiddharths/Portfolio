Published in the 5th IEEE International Conference on AI in Cybersecurity (ICAIC), 2026.

Overview

Detecting attacks on IoT networks usually means shipping every device's traffic to one central model. That is a privacy problem, and on low-bandwidth links it is also a cost problem. This first-author paper asks whether separate organisations can train one intrusion detector together without sharing their traffic, and without saturating the network while they do it.

The answer is a hybrid federated architecture: each organisation trains a tabular Transformer and an XGBoost specialist on its own data, and only the Transformer's small LoRA adapter weights are shared. The result is 97.98% accuracy on 2.4 million test flows from CICIoT2023, with 89.5% less data sent per round than standard federated averaging.

Dataset & Preparation

CICIoT2023 (University of New Brunswick) holds 46.7 million flows with 47 features across 34 classes and more than 80 attack subtypes, and it is heavily imbalanced: benign and flood traffic dwarf attacks such as SQL injection and XSS. An early centralized model scored 0% on several of those rare classes, which set the preprocessing priorities:

  • Rebalancing: every class was upsampled to at least 50k rows and capped at 1M, giving 16.08M rows.
  • Feature pruning: seven weak or redundant fields (e.g. Srate, LLC, Magnitue) were dropped, leaving 39 features.
  • Federated split: the data was divided into four simulated organisations of about 4.02M rows each, stratified by label.
  • Class weighting: inverse-frequency weights in the cross-entropy loss keep the rare classes from being ignored.

Model Components

1. Transformer Backbone (with LoRA)

A tabular Transformer (embedding size 128, 3 layers, 4 attention heads) learns how the flow features interact. LoRA adapters sit inside it: instead of updating full weight matrices, each client learns small low-rank matrices, and those are the only weights that ever leave the client.

2. XGBoost Specialist

Alongside it, an XGBoost model (200 trees, depth 6) learns sharp, tree-shaped decision boundaries on fields such as packet counts and flags, which suits volumetric attacks. It stays on its client and is never shared.

3. Learnable Fusion Head

A small MLP takes both models' class probabilities and learns how to combine them into the final prediction.

Federated Methodology

Standard federated averaging (FedAvg) sends every trainable parameter to the server each round. Here each client trains locally, then sends only its LoRA adapter matrices; the XGBoost model and the local heads stay private.

Communication Efficiency: Only the LoRA adapter updates (ΔW) are transmitted to the central server.

This reduces the payload from 468 KB (Full Model) to just 49 KB per round.

The server aggregates these lightweight updates using weighted averaging based on the client's sample size (nk), ensuring fairness across heterogeneous devices.

Experimental Results

After 4 communication rounds the system reached 97.98% accuracy on 2,412,292 test flows (weighted F1 0.9803). Accuracy held steady across rounds (97.91% → 97.84% → 97.99% → 98.00%) and across clients (97.94% to 98.00%). For comparison, a centralized MLP baseline reached 77.02% validation accuracy.

Communication Analysis

Sharing only the low-rank matrices cuts the parameters sent per round from 117,248 to 12,288, small enough for constrained links such as LoRaWAN or LTE-M.

Method Trainable Params Payload Size Reduction
Standard FedAvg 117,248 ~468 KB 0%

Conclusion

Four organisations trained one intrusion detector without sharing raw traffic, reaching 97.98% accuracy while sending 89.5% less data per round than standard federated averaging. The paper, published at IEEE ICAIC 2026, combines a hybrid Transformer and XGBoost ensemble with LoRA-only updates for federated IoT security. The open problem is the rare, stealthy classes, where reconnaissance and SQL injection still trail the volumetric attacks.
